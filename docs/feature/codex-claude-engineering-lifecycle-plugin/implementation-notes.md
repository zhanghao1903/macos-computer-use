## Delivered structure

The new sibling plugin is
`plugins/codex-claude-engineering-lifecycle/`. The existing
`plugins/codex-engineering-lifecycle/` plugin remains unchanged.

The plugin contains:

- three role skills: `hybrid-workflow-init`, `hybrid-requirements`, and
  `hybrid-main`;
- explicit-only packaged copies of `feature-lifecycle`,
  `product-workflow-gate`, `technical-plan-write`,
  `technical-plan-review`, and `pr-review`;
- the existing deterministic `workflowctl.py` lifecycle runtime under an
  isolated state namespace;
- a new `claudectl.py` cross-application bridge;
- separate Claude Frontend and Review system prompts;
- five Claude transport schemas plus the eight lifecycle schemas;
- offline fake-Claude, contract, layout, skill, parity, workflow, and bridge
  tests;
- GitHub install/update/uninstall, privacy, terms, support, and recovery
  documentation.

The repository marketplace adds
`codex-claude-engineering-lifecycle` without replacing the Codex-only plugin.

## Runtime behavior

Init creates two Codex tasks and generates two distinct Claude UUIDs. The
Claude Review UUID occupies the lifecycle review endpoint so the existing
routed plan/code contracts remain deterministic without a Codex Review task.

The bridge:

- probes the configured executable and authentication before Init state;
- stores only an absolute executable path and no credentials;
- invokes Claude with an argv array and no shell;
- sends a small environment allowlist that excludes Anthropic/API token
  variables;
- creates each role using its exact `--session-id` and resumes only that UUID;
- uses `acceptEdits` for Frontend and `plan` for Review;
- binds model, turns, USD budget, timeout, role prompt, and JSON Schema;
- persists message authority before process start;
- returns saved results for identical completed retries;
- rejects message-ID reuse with different request/schema authority;
- serializes unresolved work per Claude role;
- records deterministic preflight failures as retryable `FAILED`;
- records uncertain process/output failures as `UNKNOWN`;
- recovers UNKNOWN only with the identical message, request, role, and session;
- converts an orphaned RUNNING message only after explicit confirmation that
  the original Claude process stopped.

## Frontend authority

A Claude `COMPLETED` response is not implementation authority by itself.
`verify-frontend` independently checks:

- clean worktree and unchanged requested branch;
- exact current end head;
- start-to-end ancestry;
- remote presence of the start snapshot;
- non-empty ordered commit and path sets;
- exact agreement between Claude claims and Git evidence;
- every changed path under an approved frontend prefix.

The bridge blocks and preserves the checkout on dirty state, stale/rewritten
history, claim mismatch, or path escape. It never resets or deletes evidence.

## Review authority

Plan and code requests are validated with the existing full lifecycle
contracts and must route from the configured Main task to the configured
Claude Review UUID. Claude results bind:

- message and canonical request digests;
- workflow, repository, feature, cycle, and Review session;
- the exact plan commit/composite digest or PR URL/base/head snapshot;
- structured findings whose derived counts equal declared counts.

Main persists the validated Markdown/JSON unchanged and mechanically creates
the existing lifecycle result. Claude Review has no feature-branch, merge,
release, or credential authority.

## Compatibility and public surface

This change adds a repository plugin and local helper CLIs. It does not change
the app-control Python packages, their public APIs, protocols, or package
artifacts.

The first release targets Claude Code CLI. Claude Desktop UI control and a
shared vendor-neutral cross-application protocol are intentionally out of
scope; they can be separate plugins later.

## Implementation deviations resolved

- Deterministic preflight failures now use `FAILED` rather than UNKNOWN and
  remain retryable after the executable/plugin resource is repaired.
- Status remains readable if the configured Claude executable temporarily
  disappears.
- A dedicated, confirmation-gated `mark-orphaned` transition handles Codex
  process loss without silently resuming a possibly live Claude session.
